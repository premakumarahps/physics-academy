PART 3: PREPARE FOR DEPLOYMENT (CHANGES FOR INTERNET LAUNCH)
───────────────────────────────────────────────────────────────────────────────

When ready to deploy to internet, make these changes:

3.1) UPDATE API_BASE in data.js
────────────────────────────────

FILE: data.js (Line 1)

Current (Local):
  const API_BASE = 'http://localhost:3000/api';

Change to (Internet):
  const API_BASE = 'https://your-backend.railway.app/api';

Replace "your-backend" with your actual Railway project name.


3.2) UPDATE CORS in server/index.js (For Internet)
────────────────────────────────────────────────────

FILE: server/index.js (Lines 15-24)

Current (Local only):
  const origin = req.headers.origin;
  if (origin && (origin.startsWith('http://localhost:') || origin.startsWith('http://127.0.0.1:'))) {
    res.header('Access-Control-Allow-Origin', origin);
  }

Change to (Internet):
  const origin = req.headers.origin;
  const allowedOrigins = [
    'http://localhost:3000',
    'http://localhost:5000',
    'http://127.0.0.1:3000',
    'http://127.0.0.1:5000',
    'https://yourproject.vercel.app'  // Add your Vercel domain
  ];
  if (origin && allowedOrigins.includes(origin)) {
    res.header('Access-Control-Allow-Origin', origin);
  }


3.3) UPDATE Database (If using Supabase)
──────────────────────────────────────────

IF you use Supabase for production:

FILE: server/index.js (Add at top)

  const { createClient } = require('@supabase/supabase-js');
  const supabase = createClient(
    process.env.SUPABASE_URL,
    process.env.SUPABASE_KEY
  );

Then replace file storage API endpoints with Supabase calls.

BUT: If keeping file storage on Railway:
  - Just deploy as-is
  - Railway's filesystem persists for 24 hours minimum
  - Perfect for small projects


3.4) Environment Variables for Deployment
────────────────────────────────────────────

Create .env file with:

  PORT=3000
  ADMIN_USERNAME=admin
  ADMIN_PASSWORD=your_secure_password_here
  SESSION_TIMEOUT=3600000
  NODE_ENV=production

For production, use Railway's environment variable panel instead of .env file.


PART 4: STEP-BY-STEP DEPLOYMENT GUIDE
───────────────────────────────────────────────────────────────────────────────

STEP 1: Push to GitHub
──────────────────────

$ git init
$ git add .
$ git commit -m "Initial commit: Student LMS Assessment System"
$ git branch -M main
$ git remote add origin https://github.com/yourusername/student-lms.git
$ git push -u origin main


STEP 2: Deploy Backend to Railway (5 minutes)
────────────────────────────────────────────────

1. Go to https://railway.app
2. Click "Deploy Now" → "Deploy from GitHub"
3. Select your repository
4. Railway auto-detects Node.js (your server/index.js)
5. Wait for build complete (~2-3 minutes)
6. Your backend is live at: https://[project-name].railway.app

Set Environment Variables in Railway Dashboard:
  - ADMIN_USERNAME = admin
  - ADMIN_PASSWORD = your_password
  - NODE_ENV = production

Your backend is now: https://your-project.railway.app/api


STEP 3: Deploy Frontend to Vercel (5 minutes)
───────────────────────────────────────────────

1. Go to https://vercel.com
2. Click "Add New" → "Project" → Import from GitHub
3. Select your repository
4. In "Build and Output Settings":
   - Framework: Other
   - Build Command: (leave blank)
   - Output Directory: . (root)
5. Deploy!

Your frontend is now: https://your-project.vercel.app

Set Environment Variable in Vercel:
  - REACT_APP_API_BASE = https://your-project.railway.app/api


STEP 4: Update data.js with Production URLs
─────────────────────────────────────────────

Update file:
  FILE: data.js (Line 1)
  
  Replace:
    const API_BASE = 'http://localhost:3000/api';
  
  With:
    const API_BASE = 'https://your-project.railway.app/api';

IMPORTANT: This change only applies when deployed on Vercel.
Your local development still uses localhost:3000!

Solution: Use environment variable:
  
  const API_BASE = process.env.REACT_APP_API_BASE || 'http://localhost:3000/api';

Then in Vercel dashboard, set:
  REACT_APP_API_BASE = https://your-project.railway.app/api


STEP 5: Test Live
─────────────────

1. Visit: https://your-project.vercel.app
2. Login: admin / your_password
3. Create activity + assign to student
4. Login as student
5. Take activity, submit, download PDF
6. Everything should work!

If error: Check browser console (F12) for API URL errors


PART 5: SIMULATING PRODUCTION LOCALLY (OPTIONAL)
───────────────────────────────────────────────────────────────────────────────

To test production setup locally without deploying:

5.1) Simulate Vercel + Railway separation:

TERMINAL 1 - Backend (Simulating Railway):
  $ cd server
  $ npm install
  $ npm start
  → Runs on http://localhost:3000

TERMINAL 2 - Frontend (Simulating Vercel):
  $ npx serve . --listen 5000
  → Serves from http://localhost:5000

In data.js, set:
  const API_BASE = 'http://localhost:3000/api';

This simulates:
  - Frontend on port 5000 (like Vercel)
  - Backend on port 3000 (like Railway)
  - CORS handling between them
  - Production-like separation

Test this local simulation before deploying to verify everything works!


PART 6: DATABASE MIGRATION (If upgrading from file storage)
───────────────────────────────────────────────────────────────────────────────

For small students (<1000): Keep file storage on Railway (simple, free)

For large students (>1000): Migrate to Supabase PostgreSQL

Migration steps (later, if needed):

1. Create Supabase project at https://supabase.com
2. Create tables:
   - students (id, name, username, password_hash, ...)
   - activities (id, name, code, timer_minutes, created_at)
   - questions (id, question, options, correct_answer, ...)
   - results (id, activity_id, student_id, answers, score, ...)
   - assignments (id, activity_id, student_id, assigned_at)

3. Update server/index.js to use Supabase instead of file storage

4. For images:
   - Keep using Supabase Storage (1GB free)
   - Or keep on Railway filesystem (simpler for now)

This can be done gradually - no rush for small deployment.
